## 背景

上周六，我把自己二改的 DCTimer，即 DCTimer-BLE ，相关链条都进行完善并发布了宣传视频，反响还是不错的

软件本身就是我自己一直在用在测试的，我能优化到所有我关注到的地方，所以是能保证一定的使用体验。

## 编码地位的变化

之前刷推有句话挺赞同，大概意思是现在一个软件好不好用，多取决于开发者的 Taste 以及付出的精力。编码水平已经不是高门槛了。

Agent 已经强的可怕了，想 feat 个功能，fix 个 bug，或者大量的 refactor，几句话 Vibe 一下都能做到。

DCTimer 的 BLE 功能，从技术实现上换谁来都能做，本质只是轮子的集成 + js->java 的重写，大量比较成熟的代码库可以参考。为了利于后续开发和维护，加点 spec 驱动即可。因此，对于整个软件开发过程中的编码任务，难度已经降低很多了。需要更多关注的是需求描述，Agent 协作方式，以及宣传运营。

## 对 Vibe 的看法

其实早一些时间线，Vibe 还是有点自卑的，因为自己编码水平的确低，沉淀的少，语法一窍不通，因此对自己 Vibe 的，都只能称作玩具，大多也都只是一时兴起，真正用心开发维护的东西，很少。

自从 GPT 5.4 ，Opus 4.6 之后，观察到很多软件开发的从业者，实际上也在有 Vibe 的感觉。我想，真正有强劲的古法编程水平的人，还是占很少的人数。当然，有一定的代码基础，对于 Vibe 当然是锦上添花的。

但现在逐渐对自己写的东西，开始用心去维护了。取一个好名字，写好 README.md，搭好官网，剪好视频，都挺重要的，不然都拿不到小星星💦

## 对后续维护的计划

最近收到很多反馈和建议，尤其是功能 feat。这个是不能着急推进，一直加功能的。首先应当保证稳定性，修 bug，提升细节体验，都是为后续铺路吧，不然功能一直 feat 很容易难维护的。

哎，感觉现在自己的表达能力和写作水平，更低了，很多意思完全表述不出来，感觉是在写 Memos 一样，没有一点博客的感觉。后面还是得多读读大佬们的博客学习一下。
